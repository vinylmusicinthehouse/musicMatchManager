Getting started
  • Pick A and (optionally) B CSV files exported from Discogs (Collection and/or Wantlist).
  • We read Artist, Title, Catalog #, Format, Genres, Styles, Release ID.
  • Names are normalized (diacritics/punctuation‑safe), Formats are parsed, and Genres/Styles are normalized when present.
  • You’ll see overlap/summary once A (and B) finish loading.
Export from Discogs (quick)
  1. Open your Collection or Wantlist on discogs.com (desktop is easiest).
  2. Click Export / Download CSV and save the file.
  3. No column editing needed—the loader recognizes common Discogs headers.
  4. API‑derived CSVs work too; if Release ID is present we link to Discogs.
Big libraries: if a CSV is huge, split it into parts (~10–20k rows each) and load one part at a time.
Using A & B (what gets compared)
  • Artists: compared using a normalized key (diacritics stripped, punctuation‑light). Display always shows the exact name (e.g., 10,000 Maniacs, AC/DC).
  • Releases: if a Release ID exists we match on that. Otherwise we use a stable signature of artist key + title + catalog + format (ignoring catalog values that look like grades such as VG+, G+).
  • Genres/Styles (when available): the loader ingests and normalizes Genres and Styles; it also derives {genre, style} pairs. These fields are available to any component (e.g., Top 10 Styles, future “compare by style/genre”), but they don’t change basic artist/release matching unless a component opts into them.
